绪论：数据库的世界从四个概念开始

绪论是整门课的地图：先建立起「数据 → 数据库 → DBMS → 数据库系统」的概念骨架， 再理解数据库为什么比文件系统好，最后掌握本章最重要的考点——三级模式结构与两级映像。

一、四个基本概念

这四个概念的辨析几乎每场考试都会以名词解释或选择题出现：

1. 数据（Data）
数据库中存储的基本对象，是描述事物的符号记录。关键：数据与语义不可分—— 「97」这个数字本身无意义，但「张三的数据库成绩是 97」才有意义。
2. 数据库（DB, Database）
长期存储在计算机内、有组织的、可共享的大量数据的集合。 三个关键词必须记住：永久存储、有组织、可共享。
3. 数据库管理系统（DBMS）
位于用户与操作系统之间的数据管理软件，属于系统软件。 主要功能：数据定义功能（DDL）、数据操纵功能（DML）、数据库的运行管理、建立与维护等。
4. 数据库系统（DBS）
引入数据库后的整个系统 = 数据库 + DBMS（及其开发工具）+ 应用程序 + 数据库管理员（DBA）。 注意：DBS 是最大概念，DB 和 DBMS 都包含在其中。
简答题常考「DB、DBMS、DBS 三者关系」：数据库系统（DBS）包含数据库（DB）和数据库管理系统（DBMS）；DBMS 是管理 DB 的软件；DBA 是人员角色。四者层次：DBS ⊃ { DB, DBMS, 应用程序, DBA }。

二、数据管理技术的三个发展阶段

数据管理（对数据进行分类、组织、编码、存储、检索、维护）经历了三个阶段。理解每一阶段「为什么不够好」， 就知道数据库系统好在哪里：

阶段数据管理方式主要特点／问题
人工管理阶段
20世纪50年代前		数据不保存，由程序（应用）自行管理数据不共享、不独立；一组数据对应一个程序
文件系统阶段
50年代后期～60年代		数据以文件形式长期保存，由 OS 文件系统管理有了一定独立性，但共享性差、冗余度大，数据独立性仍不足
数据库系统阶段
60年代末以来		由统一的数据管理软件（DBMS）集中管理三高两低一独立：共享性高、冗余度低、独立性强、由 DBMS 统一管理和控制
文件系统与数据库系统的本质区别：文件系统中数据由应用程序负责管理，数据面向应用；数据库系统中数据由DBMS统一管理，数据面向整个系统（可共享）。

三、数据模型：数据库的核心和基础

模型是对现实世界的抽象。数据模型分两大类：

1. 两类模型

  • 概念模型：按用户的观点建模，用于数据库设计（与现实世界打交道），典型工具是 E-R 图（实体-联系）。
  • 逻辑模型（含物理模型）：按计算机系统的观点建模，用于 DBMS 实现。 三大经典逻辑模型：层次模型（树）、网状模型（图）、关系模型（二维表，当今主流，MySQL 就是关系型）。

2. 数据模型三要素（必背）

数据结构
研究对象类型的集合，刻画静态特性——「数据库由什么组成」
数据操作
对数据的操作类型和方式，主要是查询与更新（增删改）——「能对数据做什么」
完整性约束条件
数据及其联系应遵守的规则的集合——「数据必须满足什么规则」
选择题高频：给一个模型特征判断属于哪类模型，或问「数据模型的三要素是什么」。关系模型的完整性约束包括：实体完整性、参照完整性、用户定义完整性（第5章展开）。

四、三级模式结构与两级映像（本章最重要考点）

数据库系统内部采用「三级模式」组织数据，通过「两级映像」连接，从而获得两种数据独立性。 先看结构图：

三级模式（从外到内）

外模式（子模式／用户模式）
用户能看见和使用的局部数据的逻辑结构描述。一个数据库可以有多个外模式，每个用户只能看到与自己相关的外模式——这也是安全保护的一道屏障。
模式（逻辑模式）
数据库中全体数据的逻辑结构和特征的描述，是所有用户的公共数据视图。一个数据库只有一个模式。
内模式（存储模式）
数据物理结构和存储方式的描述。一个数据库只有一个内模式。

两级映像与数据独立性

外模式／模式映像
当模式改变时，由 DBA 修改此映像，外模式可保持不变 → 应用程序不用改 → 逻辑数据独立性
模式／内模式映像
当存储结构改变时，修改此映像，模式可保持不变 → 物理数据独立性
本章最高频考点：① 三级模式各是什么、各有多少个（模式与内模式唯一，外模式可有多个）；② 两种数据独立性分别由哪个映像保证——逻辑独立性靠外模式／模式映像，物理独立性靠模式／内模式映像。记忆口诀：「映像在哪一侧断了联系，哪一侧就不用改」。

五、与 MySQL 的联系

本章理论在 MySQL 中的对应物：

-- 外模式：CREATE VIEW 创建的视图（第3章细讲）
CREATE VIEW student_scores AS SELECT name, score FROM student;

-- 模式：你创建的表
CREATE TABLE student (id INT PRIMARY KEY, name VARCHAR(50), score INT);

-- 内模式：MySQL 自动决定 InnoDB 如何在磁盘上存储（.ibd 文件、B+ 树索引）
-- 用户完全不需要关心——这正是数据独立性的体现

你写 SQL 时永远只面对模式（表），不用管数据怎么存的——这就是本章理论在真实系统中的样子。
