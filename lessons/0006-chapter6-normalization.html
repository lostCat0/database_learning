范式：什么样的表才算「好表」

本章回答一个设计问题：一张表怎样设计才不会出毛病。判断依据是函数依赖与范式。 这是全课程理论难度最高、考试分值最重的章节——但它的思考方式很朴素：一张表如果又存学生又存课程又存成绩， 改一处就要改多处（更新异常），删一条记录可能丢掉无关信息（删除异常）。范式就是消除这些毛病的设计标准。

一、函数依赖（FD）：一切的起点

函数依赖 X → Y：在表中，X 的值一旦确定，Y 的值就被唯一确定（一个学号只对应一个姓名 → 学号 → 姓名）。

完全函数依赖 / 部分函数依赖
Y 依赖整个 X 才成立 → 完全依赖；(学号, 课程号) → 成绩 是完全依赖；而 (学号,课程号) → 姓名 只依赖学号部分 → 部分函数依赖（部分依赖是坏味道的根源）。
传递函数依赖
学号 → 系别，系别 → 系主任，且系别 ↛ 学号 → 学号传递依赖于系主任。传递依赖也是坏味道。
候选码（用 FD 推）
能决定所有属性的最小属性组。推理工具：Armstrong 公理（自反、增广、传递），实际解题用「求闭包」：从属性组出发看能推出哪些属性。

二、范式阶梯（逐级收紧）

范式要求消除的问题
1NF每个分量不可再分（原子性）表中有复合属性
2NF在 1NF 基础上，消除非主属性对码的部分依赖部分依赖
3NF在 2NF 基础上，消除非主属性对码的传递依赖传递依赖
BCNF每个函数依赖的决定因素（左部）都包含候选码主属性对码的依赖

包含关系：BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF。

经典例题走一遍（考试原题型）

表 SC(sno, cno, sname, grade)，其中学号决定姓名：sno → sname；码是 (sno, cno)。

  • grade 完全依赖码 → 合格；但 sname 部分依赖码（只依赖 sno）→ 只到 1NF。
  • 分解为 Student(sno, sname) + SC(sno, cno, grade) → 消除部分依赖 → 达到 2NF。

表 SD(sno, sdept, sloc)，sno → sdept，sdept → sloc：

  • 无部分依赖（码是单个 sno）→ 已是 2NF；但 sno → sdept → sloc 是传递依赖 → 不是 3NF。
  • 分解为 SD1(sno, sdept) + DEPT(sdept, sloc) → 达到 3NF。
解题流程口诀：① 找出所有函数依赖 → ② 求候选码（闭包法）→ ③ 检查非主属性对码有没有「部分依赖」（有则非 2NF）→ ④ 检查有没有「传递依赖」（有则非 3NF）→ ⑤ BCNF 看每个依赖左部是否含候选码。分解时保持「无损连接」是底线，最好也保持函数依赖。
