数据库完整性：防的是「错」，不是「贼」

第4章防的是「非法用户」，本章防的是「合法用户写进错误数据」。三类完整性约束你在第2、3章已经见过， 本章把它们串成体系，并学习两个新武器：触发器与断言。

一、完整性的三大件（体系化回顾）

约束防什么SQL 实现手段谁检查
实体完整性主属性为空、主码重复PRIMARY KEYDBMS 插入/更新时自动检查
参照完整性引用不存在的对象FOREIGN KEY同上；违约处理可选 级联/拒绝/置空
用户定义完整性业务语义错误NOT NULL / UNIQUE / CHECK / 域约束同上
参照完整性的「违约处理」是简答题考点：当删除被参照表的元组或修改其主码时，可选三种策略——级联删除（CASCADE）、拒绝执行（NO ACTION）、设置为空（SET NULL）。选择题常给出场景让你选策略。

二、触发器（TRIGGER）：完整性的「自动保安」

约束是「静态规则」，触发器是「动态响应」——当指定事件（INSERT/UPDATE/DELETE）发生时自动执行一段过程。 语法骨架（MySQL / 标准语法）：

CREATE TRIGGER 触发器名
{BEFORE | AFTER} {INSERT | UPDATE | DELETE} ON 表名
FOR EACH ROW                -- 行级触发器：每受影响一行执行一次
BEGIN
  -- 触发动作体，可引用 NEW.列（新值）、OLD.列（旧值）
END;
触发器三要素选择题必考：触发事件 + 触发时机（BEFORE/AFTER）+ 触发动作。另外注意：触发器是 SQL 标准的一部分，属于完整性控制的高级手段，也常用于自动审计、级联业务规则。

三、断言（ASSERTION）：跨表的全面检查

CHECK 约束只能管一张表的一列/一行，而断言可以对多张表之间的联系做全局约束：

-- 例：任何时刻，每门课的选课人数不得超过 30
CREATE ASSERTION as_count CHECK
  (30 >= ALL (SELECT COUNT(*) FROM sc GROUP BY cno));

MySQL 至今不直接支持 CREATE ASSERTION（ PostgreSQL 支持），考试考的是概念：CHECK 限单表，断言管跨表。
