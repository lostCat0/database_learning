一、SQL 概述：三分钟建立全局观

SQL 最大的特点：非过程化——你只说「要什么」，不用说「怎么拿」（对比 C 语言一步步操作）。 按功能分三类，这个分类是填空/选择必考：

类别全称负责代表语句
DDL数据定义语言定义表、视图、索引的结构CREATE / DROP / ALTER
DML数据操纵语言操作表里的数据SELECT / INSERT / UPDATE / DELETE
DCL数据控制语言权限与安全GRANT / REVOKE
高频陷阱题：SELECT 属于 DML（有的教材归为「数据查询语言 DQL」单列，按王珊教材归 DML）；DROP 删的是表结构+数据，DELETE 只删数据不动结构。

二、数据定义（DDL）：亲手建出三张表

建表语法与五类常用约束：

CREATE TABLE 表名 (
  列名  数据类型  [约束],
  ...
  PRIMARY KEY (列),                    -- 主码约束（实体完整性）
  FOREIGN KEY (列) REFERENCES 别表(列), -- 外码约束（参照完整性）
  UNIQUE (列),                          -- 唯一值
  NOT NULL,                             -- 非空
  CHECK (条件)                          -- 用户定义完整性，如 CHECK(grade BETWEEN 0 AND 100)
);

注意看：第2章的三类完整性约束，在这里全部落地成了具体语法——实体完整性 = PRIMARY KEY，参照完整性 = FOREIGN KEY，用户定义完整性 = CHECK / NOT NULL / UNIQUE。

三、数据查询：SELECT 是 SQL 的灵魂

单表查询的完整结构（顺序固定）：

SELECT   列1, 列2        -- ③ 挑列（对应关系代数 π 投影）
FROM     表名             -- ① 数据从哪来
WHERE    行条件           -- ② 挑行（对应 σ 选择）
GROUP BY 分组列           -- ④ 分组
HAVING   组条件           -- ⑤ 筛选组（组级 WHERE）
ORDER BY 排序列 [DESC]    -- ⑥ 排序（DESC 降序，默认 ASC 升序）
LIMIT    n;               -- ⑦ 只取前 n 行（MySQL 方言）

记忆执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY（数据库实际先找表、再筛行、再分组、最后才挑列排序）。理解这个顺序，「为什么 HAVING 里能用聚合函数而 WHERE 不能」就一目了然——分组发生在挑列之前。

四、连接查询：把第2章的 ⋈ 敲出来

SELECT s.sname, sc.grade
FROM student s JOIN sc ON s.sno = sc.sno   -- 自然连接的思想：按公共列学号对上
WHERE ...;

对应第2章：这就是 Student ⋈ SC。多表连接就把多个 JOIN 串起来。 外连接（LEFT JOIN 保留左表全部行）和嵌套查询（子查询 WHERE sno IN (SELECT ...)）是同族知识点，教材同章，练习脚本里有对应练习。

五、数据更新：INSERT / UPDATE / DELETE

INSERT INTO 表 VALUES (值1, 值2, ...);              -- 插入整行
UPDATE 表 SET 列 = 新值 WHERE 条件;                  -- 一定要带 WHERE，否则全表修改！
DELETE FROM 表 WHERE 条件;                           -- 一定要带 WHERE，否则清空全表！

六、视图：外模式的化身

视图是虚表——只存一条查询语句的定义，不存实际数据；查询视图时才临时计算。 它正是第1章「外模式」在 SQL 里的落地：不同用户通过不同视图只看见自己该看见的数据。

CREATE VIEW 视图名 AS SELECT ...;   -- 定义（不执行查询）
DROP VIEW 视图名;                    -- 删除视图（表不受影响）
