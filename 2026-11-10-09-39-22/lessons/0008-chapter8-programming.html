数据库编程：SQL 进阶为程序

交互式 SQL 一句一句敲，真实应用需要把 SQL 嵌进程序里跑批量逻辑。本章讲三种编程形态： 嵌入式 SQL、存储过程/函数、触发器，以及连接两者的桥梁——游标。

一、嵌入式 SQL 与主语言的通信

把 SQL 语句嵌进 C/Java 等主语言中，两者「语言不通」，靠三样东西通信（简答必背）：

共享变量（主变量）
主语言声明、SQL 可引用的变量，SQL 中用 :变量名 引用（加冒号区分列名）。
游标（Cursor）
SQL 的查询结果是集合，主语言只能逐条处理——游标把集合变成一行一行的游标记录。
SQL 通信区（SQLCA）
反馈执行状态（如 sqlcode），供主语言判断成功与否。

二、存储过程与函数

存储过程是存在数据库服务器里、预编译的一段过程化 SQL（含 IF/WHILE/变量），应用端 CALL 调用。 考点：它相比客户端逐句发 SQL 的优势——预编译执行快、减少网络流量、封装业务逻辑、可授权。

DELIMITER //
CREATE PROCEDURE get_age(IN p_sno CHAR(4), OUT p_age INT)
BEGIN
  SELECT sage INTO p_age FROM student WHERE sno = p_sno;
END //
DELIMITER ;
CALL get_age('S2', @age); SELECT @age;

函数（FUNCTION）与过程类似，但必须 RETURN 一个值，可用在 SELECT 表达式里。

三、游标：集合到单行的桥梁

DECLARE cur CURSOR FOR SELECT sname FROM student;  -- 声明
OPEN cur;                    -- 打开（执行查询）
FETCH cur INTO v_name;       -- 逐行取
CLOSE cur;                   -- 关闭
游标四步曲「声明 → 打开 → 逐行提取 → 关闭」是填空高频；为什么要游标（SQL 面向集合 vs 主语言面向单条记录）是简答高频。
