数据库术语表

随章节持续扩充 · 术语与王珊《数据库系统概论》保持一致

第1章 绪论

数据（Data）
数据库中存储的基本对象，是描述事物的符号记录。数据的含义称为语义，数据与其语义不可分。
数据库（DB, Database）
长期存储在计算机内、有组织的、可共享的大量数据的集合。特征：永久存储、有组织、可共享。
数据库管理系统（DBMS）
位于用户与操作系统之间的数据管理软件，是基础软件。主要功能：数据定义、操纵、组织存储、运行管理、建立维护。
数据库系统（DBS）
引入数据库后的整个系统：数据库 + DBMS（及其开发工具）+ 应用程序 + 数据库管理员（DBA）。
数据模型（Data Model）
对现实世界数据特征的抽象，是数据库系统的核心和基础。三要素：数据结构、数据操作、完整性约束条件。
概念模型
按用户观点对数据和信息建模，主要用于数据库设计，典型工具是 E-R 图（实体-联系方法）。
逻辑模型
按计算机系统的观点对数据建模，用于 DBMS 实现。层次模型、网状模型、关系模型都属于逻辑模型。
模式（Schema）
数据库中全体数据的逻辑结构和特征的描述，仅涉及型的描述，不涉及具体值。一个数据库只有一个模式。
外模式
数据库用户能够看见和使用的局部数据的逻辑结构和特征的描述，是与应用有关的数据的逻辑表示。一个数据库可以有多个外模式。
内模式
数据物理结构和存储方式的描述，是数据在数据库内部的组织方式。一个数据库只有一个内模式。
外模式／模式映像
定义外模式与模式之间的对应关系。当模式改变时，只需修改此映像，外模式保持不变 → 保证逻辑数据独立性。
模式／内模式映像
定义模式与内模式之间的对应关系。当存储结构改变时，只需修改此映像，模式保持不变 → 保证物理数据独立性。

第2章 关系数据库

域（Domain）
一组具有相同数据类型的值的集合。如整数、{男, 女}。
笛卡尔积（Cartesian Product）
给定一组域 D1…Dn 的笛卡尔积是所有域上取值的组合的集合，每个元素 (d1,…,dn) 叫一个 n 元组。
关系（Relation）
笛卡尔积 D1×…×Dn 的有意义的子集称为在域 D1…Dn 上的关系，记作 R(D1,…,Dn)，本质是规范的二维表。
候选码（Candidate Key）
关系中能唯一标识一个元组的属性或属性组，且不含多余属性。可有多个。
主码（Primary Key）
从多个候选码中人为选定一个作为主码（主键）。一个关系只有一个。
主属性 / 非主属性
包含在任何候选码中的属性称主属性；否则称非主属性。
外码（Foreign Key）
关系 R 中的属性组，虽不是 R 的码，却与另一个关系 S 的主码相对应，则它是 R 的外码。用于建立表间联系。
实体完整性
主属性不能取空值。因为主码唯一标识元组，空值则无法标识。
参照完整性
外码取值要么为空，要么等于被参照关系中某个主码值。保证表间引用合法。
用户定义的完整性
针对具体应用的约束，如成绩取 0~100、性别只能取 {男,女}。
关系代数
以关系为运算对象的抽象查询语言。传统集合运算：并 ∪、差 −、交 ∩、笛卡尔积 ×；专门运算：选择 σ、投影 π、连接 ⋈、除 ÷。SQL 是它的工程实现。
自然连接（Natural Join）
等值连接的特例：比较属性相同，且去掉重复列。若两关系无公共属性，结果为笛卡尔积。
除运算（Division）
R ÷ S：找出 R 中那些「在 S 的全部属性值上都满足」的元组的其余属性值。典型场景：「查询选修了全部课程的学生」。

第3章 SQL 语言

SQL（结构化查询语言）
操作关系数据库的标准语言，特点是非过程化（只描述「要什么」）。按功能分 DDL、DML、DCL 三类。
DDL（数据定义语言）
定义数据库对象的结构：CREATE / ALTER / DROP。作用于表、视图、索引等。
DML（数据操纵语言）
操作表中的数据：SELECT / INSERT / UPDATE / DELETE。
DCL（数据控制语言）
权限管理：GRANT / REVOKE（第4章安全性展开）。
基本表（Base Table）
独立存在的表，实际存储数据的二维表。
视图（View）
虚表，只存放查询定义、不存数据；查询时临时计算。对应三级模式中的外模式。
PRIMARY KEY / FOREIGN KEY
主码约束（实体完整性的落地）/ 外码约束（参照完整性的落地）。
CHECK / NOT NULL / UNIQUE
用户定义完整性的落地：取值范围 / 非空 / 唯一。
聚合函数
COUNT、SUM、AVG、MAX、MIN，对一组值计算单一结果，常与 GROUP BY 配合。
WHERE vs HAVING
WHERE 在分组前逐行筛选（不能用聚合函数）；HAVING 在分组后筛选组（可用聚合函数）。
DROP vs DELETE vs TRUNCATE
DROP 删除表结构+数据；DELETE 逐行删数据（可带 WHERE，可回滚）；TRUNCATE 快速清空全表数据、保留结构。

第4章 数据库安全性

自主存取控制（DAC）
用户可自主定义和转授权限。手段：GRANT 授权 / REVOKE 收权；WITH GRANT OPTION 允许转授；收回时级联回收。
强制存取控制（MAC）
主体有许可证级别、客体有密级；许可证 ≥ 密级才可读，仅许可证 = 密级才可写，用户不能自主改变。
审计（Audit）
把用户操作自动记入审计日志，属于事后追责手段，耗资源，可选启用。

第5章 数据库完整性

违约处理
参照完整性被破坏时可选：级联删除（CASCADE）/ 拒绝（NO ACTION）/ 置空（SET NULL）。
触发器（TRIGGER）
事件驱动的过程：触发事件（增删改）+ 触发时机（BEFORE/AFTER）+ 动作体；行级触发器每受影响行执行一次。
断言（ASSERTION）
跨多表的全局完整性约束（CHECK 只限单表）；MySQL 尚不支持。

第6章 关系数据理论

函数依赖 X→Y
X 值确定则 Y 值唯一确定。分完全/部分依赖；X→Y、Y→Z 则 X 传递依赖 Z。
范式阶梯
1NF（原子性）→ 2NF（消除部分依赖）→ 3NF（消除传递依赖）→ BCNF（每个决定因素含候选码）。
闭包 / Armstrong 公理
求候选码的工具：自反、增广、传递三条推理规则；X⁺ 表示 X 能推出的全部属性。
无损连接 / 保持函数依赖
模式分解的两个质量标准：分解后可 JOIN 还原原表；分解后函数依赖仍可判定。

第7章 数据库设计

设计六阶段
需求分析（产出数据字典）→ 概念结构设计（E-R 图）→ 逻辑结构设计（关系模式）→ 物理设计（索引）→ 实施 → 运行维护。
E-R 图冲突
集成时三类冲突：属性冲突、命名冲突（同名异义/异名同义）、结构冲突。
E-R 转换规则
实体→关系；1:1 并入任一端；1:n 并入 n 端；m:n 独立成新关系（两端码组合为主码）。

第8章 数据库编程

嵌入式 SQL 通信三件套
主变量（共享变量，SQL 中加冒号引用）、游标、SQL 通信区（SQLCA）。
游标（Cursor）
把面向集合的查询结果转为逐行处理：声明 → OPEN → FETCH → CLOSE。
存储过程
存于服务器、预编译、可含逻辑（IF/WHILE）的过程，CALL 调用；函数须 RETURN 值。

第9章 查询处理与优化

查询处理四步
查询分析 → 查询检查（语义/权限，生成关系代数树）→ 查询优化 → 查询执行。
代数优化启发式规则
选择/投影尽早做、笛卡尔积改连接、公共子表达式只算一次。
物理优化
按代价（磁盘 I/O）选算法：选择用全表扫描/索引扫描；连接用嵌套循环、排序-合并、哈希等。

第10章 数据库恢复

事务（Transaction）
要么全做要么全不做的工作单位；ACID：原子性、一致性、隔离性、持续性。
故障分类
事务内部故障、系统故障（断电，内存丢磁盘完好）、介质故障（磁盘坏）、病毒。
恢复技术
转储（静态/动态 × 海量/增量）+ 日志；黄金法则「先写日志后写库」；未提交事务 UNDO、已提交未写盘事务 REDO；检查点缩短恢复扫描范围。

第11章 并发控制

并发四问题
丢失修改、不可重复读、读脏数据、幻影读（针对插入新行）。
S 锁 / X 锁
共享锁与共享锁相容，其余组合均不相容。三级封锁协议逐级解决丢失修改、脏读、不可重复读。
两段锁协议（2PL）
扩展阶段只加锁、收缩阶段只放锁；保证可串行化，但不防死锁。
死锁诊断
等待图中出现回路即死锁；预防用一次封锁法/顺序封锁法，解除时选代价最小事务回滚。
